# 阵容与分钟预测：第三轮优化

目标：改进胜率模型的上游出场分钟信息。当前实现与冻结主模型分开，没有证明胜率或 ROI 提升。

## 可复现的结果

在 2023/24、2024/25、2025/26 三个赛季的 7,290 个球队比赛样本、89,651 个球员比较记录上：

| 分钟方案 | 平均绝对误差 MAE ↓ | 均方根误差 RMSE ↓ |
| --- | ---: | ---: |
| 旧模型实际用于实力计算的分钟 | 7.300 | 10.729 |
| 按比例分满 240 分钟、每人上限 40 | 7.531 | 10.760 |
| 学习条件均值 | 7.170 | **10.261** |
| 学习条件中位数 | **6.995** | 10.426 |

中位数模型 MAE 降低约 4.2%；均值模型 RMSE 降低约 4.4%。两个学习模型的相应指标在三个赛季均改善。均值适合研究期望贡献，中位数适合研究绝对误差；不能只因为中位数 MAE 更低就把它当期望分钟。

“强制分满”方案失败，未替换进主模型。它把未能预见的复出球员分钟分给上一场打过的人，说明正确的分钟总量不等于正确的阵容。

## 如何避免伪提升

- 候选球员只来自球队前一场的名单，不使用本场实际参与者预测。
- 评估集合包含预测名单和实际出场名单的并集：预测会打却缺阵的球员实际为零，未预见的复出球员预测为零；不只给出场球员打分。
- 去掉每队每季首场，因为没有前场名单。
- 实际分钟按每队比赛合计归一到 240，控制加时影响；这是常规时间份额代理，不是直接预测含加时原始分钟。
- 学习模型只使用上一场分钟、历史预期分钟、本季此前出场次数、球队休息天数和上一场出场人数。每个评估赛季只在更早赛季训练。
- 两个固定的梯度提升回归方案，分别采用平方误差和绝对误差；120 次迭代、最多 15 个叶子、叶子至少 100 样本、L2=10，不在本次评估集搜索参数。
- 同样的历史赛季已经反复被研究；结果属于探索性证据，还需要未来比赛验证。

这些学习模型的预测不构成总和恰为 240 的联合轮换。由于仍缺少伤病和复出信息，均值模型平均有约 18.9 分钟未分配；中位数模型约 12.0 分钟。不能直接拿未分配分钟全部填成低水平替补，然后宣称提升球队实力预测。下一步需要统一阵容信息、分钟与胜率模型的训练/部署口径。

## 同时完成的研究接口

`src/rotation_research.py` 增加：

- 为当前名单中的本季尚未出场球员回退到上一季分钟；未知球员使用显式标记的 12 分钟研究先验，不再直接从名单消失。这不是已验证的新秀上场预测。
- Out 为零；Probable、Questionable、Doubtful 分别参与“全部不确定球员出场 / 全部不出场”的敏感性情景。没有擅自设定 50% 或其他出战概率。
- 缺失状态直接阻止输出，不默认健康。名单必须完整覆盖输入球队花名册。
- 明确每位球员分钟上限和球队未分配分钟；40 分钟为默认建模上限，不是医学判断或硬规则。

当前情景接口仍使用可解释的历史分钟先验与约束分配。新学习模型先保持独立评估，因为它学到的是包含缺阵概率的无条件分钟，不能直接冒充“确认出场时的分钟”再次套用伤病情景。输出也不是胜率预测或投注建议。

## 赔率与伤病时间快照

`src/pregame_snapshots.py` 支持将外部数据记录为独立 JSON 文件：

- `observed_at`：来源声明的时间；`received_at`：本地实际保存时间；`tip_utc`：开赛时间。
- 验证来源时间不晚于接收时间、接收发生在开赛前；拒绝缺失时区。
- 赔率默认最多过期 5 分钟，伤病快照最多过期 6 小时；这是当前研究过滤规则，不是官方有效期。
- 验证十进制赔率、市场类型、状态、重复球员及分钟限制。
- 文件用内容 SHA-256 命名并排他创建，不覆盖已有快照。
- 快照不是来源真实性的独立证明。还需供应商历史记录或外部时间凭证；当前名单 CSV 也尚缺采集时间，不能据此重建旧日期的历史阵容。

尚未连接博彩公司/赔率服务，也没有采集到真实报价快照。不从收盘赔率倒造赛前记录，不运行真实下注。

输入格式（下列占位符必须替换为真实来源值）：

```json
{
  "kind": "odds", "game_id": "0022600001",
  "source": "真实来源URL或供应商标识", "bookmaker": "真实博彩公司",
  "market": "moneyline", "observed_at": "带时区的实际报价时间",
  "tip_utc": "带时区的开赛时间", "home_decimal": 1.9, "away_decimal": 2.0
}
```

上面的赔率仅展示字段格式，不是真实报价。

伤病快照使用 `kind: availability`，保留 `game_id/source/observed_at/tip_utc`，另有整数 `team_id` 和 `players` 数组；每项含整数 `player_id`、`status`，可选 `minute_cap`。必须提供球队全体名单，未列入官方报告的人只有在已确认该队提交了完整报告后才可标为 Available。原来按文件日期解析的 PDF 不能自动视为符合此要求的完整快照。

运行：

```sh
.venv/bin/python src/rotation_research.py
.venv/bin/python src/pregame_snapshots.py --input /path/to/real_payload.json
.venv/bin/python src/rotation_research.py --snapshot /path/to/recorded_availability.json
.venv/bin/python -m unittest discover -s tests -v
```

详细结果、每季训练截止日期、特征与输入哈希见 `rotation_research/summary.json`；逐球员分钟评估见 `rotation_research/minutes.csv.gz`。

全部 15 项测试通过，新增检查包括复出回退、未来信息、分钟上限与不足、不确定球员情景、重复状态、过期/未来赔率和不可覆盖保存。未改动冻结实盘权重、历史预测或自动运行脚本。
